# License Server 1.8.0: what changed

Server side of the branding portal (agencies set white-label branding once on subtleforms.com, SubtleForms Pro applies it on client sites), the plan table text, and bug LS-06. Every change has tests in tests/integration.

Database: the schema version moves to 7. Three new tables (sfls_branding, sfls_branding_revisions, sfls_branding_sites) are created on the next load by the existing upgrade check, nothing needs copying. The upgrade also asks for a rewrite flush so the new My Account endpoint resolves. "Delete all data when the plugin is deleted" now also drops the three tables and removes uploads/sfls-branding.

## LS-06: a new site with a free seat is no longer blocked by others

Why: anyone who knew a key could burn the per-key failure budget from other addresses and make every request for that key answer 429, including a legitimate new site.

What: failures are budgeted per key, address and site (the "pair" bucket). A valid key asked by a site that is not activated yet but could be (free seat, or a staging site) only counts against its own pair and is never blocked by failures of other pairs. Requests that cannot succeed (unknown key, license not active, no free seat) also count towards a separate per-key ceiling, ten times the limit and scaled by the sites of the license. Activated sites keep their own key-and-site bucket. Tests: RateLimitTest, RestApiTest.

LS-05 is page content outside this repository and is not part of this change.

## Plans: MCP server and branding portal text

Why: the plan table is the source of the pricing cards and the Paddle product text.

What: "MCP server for AI assistants" is a common item of every plan. The white_label feature label now reads "Branding portal for your clients' sites, white label and WPML/Polylang translation", so the Agency text mentions the portal. Feature slugs are unchanged. Test: PlansAndVersionTest.

## Branding storage and POST /sfls/v1/branding

Why: the license key is what client sites hold, so branding is stored per license.

What: class SFLS_Branding stores profile, integer version, enabled flag and the last ten revisions (who, when, action, profile), and logs the client sites that fetched it (site address, version, time). Every save bumps the version; removing branding sets enabled to false and also bumps it. Validation follows the contract: text lengths in characters, https-only logo address ending in an image extension, http or https for the other addresses, no credentials in addresses, booleans, unknown keys dropped. The endpoint uses the validate rate limits and error shape: 404 license_not_found, 400 missing_parameters and invalid_version, 403 expired or suspended, 403 domain_not_activated. A license in its grace period is served. A plan without white_label, or no saved branding, answers enabled false and version 0. When the site sends the current version the answer has unchanged true and no profile. /license/validate, /license/status, activate and connect answers gain branding_version (0 when none), and validate and status also carry it in data.branding_version. Tests: BrandingTest.

## My Account > Branding

Why: agencies need to manage branding without support.

What: a Branding menu entry only for customers with an active license whose plan includes white_label, a license selector for several licenses, the form with every field, a preview of the app header, menu entry and Plugins screen row that follows the form as you type, the client sites with the version each fetched, and the versions list with Restore and Remove branding. Every action checks a nonce bound to the license, a signed-in user and ownership of the license, and the plan and license state again. A refused form keeps what was typed. Logo uploads are checked by image content (PNG, JPEG, GIF, WebP; the file name and browser type are ignored), up to 1 MB, refused when they also contain code, stored under a random name in uploads/sfls-branding with script execution denied, and the old file is deleted when the logo is replaced or removed. Restoring a version whose uploaded logo was already deleted restores the rest and says so. Styles are in assets/css/sfls-front.css, the preview script in assets/js/sfls-branding.js. Tests: BrandingPortalTest.

## License screen panel

Why: support needs to see what a customer's clients are on.

What: a read-only Branding panel on the license edit screen with the state, version, last change, sites that fetched it and the revisions, and a link in the History list. Test: BrandingPortalTest.
