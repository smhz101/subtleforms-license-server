# Changes in 1.9.2

## Added

- Cancel auto-renew opens Paddle's cancellation flow (survey and offer) on live accounts; falls back to the direct cancel if the flow cannot load.
- The server now checks its signing key every day, when a Licenses screen opens, on any admin screen (at most every five minutes) while a failure notice is showing, and from a check that a refused signed route schedules. If SFLS_SIGNING_SECRET_KEY is missing, malformed, damaged or does not belong to the public key Pro ships, an error notice stays on the admin screens and the admin address gets one email a day ("SubtleForms license server: signing key check failed"), and one more when it is fixed. Overlapping requests send one email each. While the key is unusable the signed routes answer 503 signing_unavailable instead of an unsigned 200, so Pro sites keep their last known license state. This fails closed: run wp sfls signing status on production before deploying (see the README, section 10).

## Fixed

- The versions list and the My Account downloads page no longer offer stable versions above the version made the latest with "Make this the latest", and a download link signed before that rollback no longer serves a version above it (410, check for updates again). A My Account button that still names such a version goes back to the downloads page with a notice and signs nothing.
- The package address in an update check now names the version it offers, so a site that checked for updates before a new release was published downloads the version it was offered. A version that was yanked, unpublished to a draft, rolled back below with "Make this the latest", or is on another update channel answers "check for updates again" (410) instead of a package that does not match, and a stable site can no longer fetch a beta by editing the version in the address.
- Switching a license key is no longer refused by the shared request limit when several sites on one host switch at once: freeing the old key has its own, higher limit.
- A seat is now kept for a site address with its path, so a copy of a site in a subdirectory (example.com/staging) no longer shares the seat of the site at the root, and deactivating one leaves the other. A host-only seat that exists when the server updates is marked as a legacy seat once, by the update itself, and never again from the version a site reports; a stored plugin version never goes down. One host/path site may join a legacy seat and share it, any further path on that host takes a seat of its own, and a legacy seat that has been quiet for 36 hours is handed to the subdirectory site that sends its path (deactivating never does that) or dropped by the daily job once its joined site holds the seat, never when the seat count is read. A site removed in the account or in wp-admin is told so (site_removed) for 30 days, and a connect code for a site with a percent-encoded path now works.
