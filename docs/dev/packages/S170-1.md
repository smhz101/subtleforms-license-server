# Package S170-1: License ownership, refunds and abuse

Repository: `subtleforms-license-server`. Release: Server 1.7.0. Branch from `release/1.7` as `pkg/S170-1`. Owner: Claude.

Standing rules: .cursor/rules/subtleforms-license-server.mdc. Bugs below are the whole task; each one needs a regression test.

## Instructions
Security and money first. Licenses belong to a user id, not an email that can change. Keep every existing test passing.

## Bugs (10)

### LS-01 (P1) Still open
- Repro: 1. A guest buys a license as victim@x (no account). 2. Any other signed-in customer opens My Account > Account details and changes the email to victim@x (no password or confirmation needed). 3. Open My Account > Licenses.
- Expected: Licenses only visible to the verified owner.
- Actual: The victim's key is shown in full, with Download, Renew, Upgrade and Deactivate. Reproduced: qa-ls-buyer changed email to the renewal-loophole buyer's address and saw key SFP-398C250F-...
- Likely cause: SFLS_Licenses::user_owns() and for_user() match customer_email (includes/class-sfls-licenses.php:210-234); the connect flow and downloads rely on it. Link licenses to user_id at checkout or on a verified email claim, and do not match by email for accounts whose email changed after the order.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-02 (P1) Still open
- Repro: Signed out, buy Starter with cheque, admin completes the order, click Download Pro in the email or on the thank-you page.
- Expected: Buyer can download Pro.
- Actual: Login form only; no account was created at checkout and registration is off (woocommerce_enable_signup_and_login_from_checkout=no, woocommerce_enable_myaccount_registration=no). The buyer has a key but no way to get the zip.
- Likely cause: The plugin does not force account creation for license carts (no woocommerce_checkout_registration_required filter in includes/). Either require an account for license orders or give guests a signed download link in the email.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-03 (P2) Still open
- Repro: Upgrade Starter to Pro (order 6415, $50), complete, then refund it in full. Separately renew (order 6422, $79), complete, refund.
- Expected: Upgrade reverted to Starter; renewal year removed.
- Actual: Order refunded, license still Pro with 5 sites; renewal expiry still 2028-10-14.
- Likely cause: SFLS_Woo::suspend_for_order() only touches licenses whose order_id equals the refunded order (includes/class-sfls-woo.php, suspend_for_order). Renewal and upgrade orders reference the license through _sfls_license_ids only.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-04 (P2) Still open
- Repro: Signed out, open /?sfls_buy=3004 (Starter Renewal, $39) and check out.
- Expected: Renewal products only for existing license holders.
- Actual: Cart accepts it (302 to checkout) and completion issues a new Starter key for $39 instead of $49.
- Likely cause: handle_cart_links()/buy() accept any license product; issue_for_order() falls back to create() when renewable_license() finds nothing (includes/class-sfls-woo.php).
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-06 (P2) Still open
- Repro: Send 5 validate requests for one key from 5 different IPs with a limit of 5 (temporary filter), then a 6th from a new IP.
- Expected: A new IP with a valid key is served.
- Actual: 429 with Retry-After for every IP: anyone who knows a key (former contractor, leaked in a support ticket) can keep the license from validating and updating. With the default 30 per 10 minutes per key, an Agency license on many sites updating at the same time also hits 429 on /update/package.
- Likely cause: limit_license_request() applies a per-key bucket to all callers (includes/class-sfls-rest.php). Count only failures per key, or key plus domain, and scale with sites_allowed.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-07 (P2) Still open
- Repro: Starter key already on 1 site; activate myshop.wpengine.com, dev.realclient.com.
- Expected: Production hosts use a seat.
- Actual: Both activated with is_local true and no seat used. *.wpengine.com is the WP Engine production primary domain; *.kinsta.cloud is used for live sites; "dev." and "test." prefixes and a substring test (".wpengine.com" anywhere in the host) are easy to abuse.
- Likely cause: is_local_domain() (includes/class-sfls-licenses.php:495-506). Use WP Engine "stg"/"dev" install patterns, exact suffix matches, and an admin setting for the list.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-08 (P2) Still open
- Repro: Request http://localhost:8899/wp-content/uploads/sfls-private/subtleforms-pro-2.2.0.zip without auth.
- Expected: 403.
- Actual: 200 and the zip. Protection depends on .htaccess (Apache) or a hand-added Nginx rule; file names are predictable.
- Likely cause: Releases are stored as subtleforms-pro-<version>.zip. Store under a random file name (or outside the web root) so a missing server rule does not leak Pro.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-13 (P3) Still open
- Repro: Link an order to a subscription (subscription.activated), then send subscription.past_due whose occurred_at is later than the activated event but earlier than the moment the link was processed.
- Expected: Applied.
- Actual: Skipped as "stale".
- Likely cause: link_licenses() sets billing_synced_at to current_time() instead of the event's occurred_at (includes/class-sfls-woo-paddle-orders.php:506).
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-15 (P3) Still open
- Repro: /connect-site/ with return=http://...
- Expected: https only outside local sites.
- Actual: http accepted, so the one-time code travels in clear text.
- Likely cause: scheme check allows http.
- Report: docs/dev/qa/2.3.3/license-server.md

### LS-16 (P3) Still open
- Repro: Review data retention.
- Expected: IPs and payloads pruned or erasable.
- Actual: Activation log (IP per event) and wp_sfls_paddle_events are never pruned; uninstall leaves user meta _sfls_paddle_customer_id and stale lock options sfls_issue_lock_*, sfls_paddle_lock_*. Full license keys appear in download URLs (server access logs).
- Likely cause: uninstall.php, class-sfls-releases.php signed_url().
- Report: docs/dev/qa/2.3.3/license-server.md
