A seat is now kept for a site address with its path, so a copy of a site in a subdirectory (example.com/staging) no longer shares the seat of the site at the root, and deactivating one leaves the other. A host-only seat from an older Pro is handed to the subdirectory site that sends its path once it has been quiet for 36 hours, deactivating never does that, and while such a seat exists it counts as one seat together with the host/path sites of the same host, so nothing breaks on upgrade; on a path-based multisite the root keeps that seat alive, its subsites activate on their own and share it until it goes quiet, and from then on every subsite takes a seat of its own. A site removed in the account or in wp-admin is told so (site_removed) for 30 days, and a connect code for a site with a percent-encoded path now works.
